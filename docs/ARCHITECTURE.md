# Архитектура и предварительная проверка

## Ограничения README

Проверено перед реализацией 20 октября 2026:

1. GitHub очищает HTML, в том числе scripts, inline styles и class/id: [github/markup](https://github.com/github/markup).
2. Поэтому React, WebGL и интерактивная камера требуют отдельной страницы. README содержит обычное изображение, обёрнутое ссылкой.
3. SVG сделан автономным; ни JS, ни `foreignObject`, ни iframe. Alt-текст и обычные ссылки сохраняют смысл без картинки.
4. GitHub проксирует/кеширует изображения; обновление файла не гарантирует моментального обновления всех просмотров.
5. Pages поддерживает статические сайты и deployment через workflow: [GitHub Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Краткий план

```text
GitHub public REST API
        │ token only in Actions runner
        ▼
collector → strict allowlist → city.json
                                │
                      ┌─────────┴──────────┐
                      ▼                    ▼
                React / Three.js       SVG generator
                      │                    │
                      └─────────┬──────────┘
                                ▼
                         Pages artifact
                                │
                  profile README image link
```

Используются `/users/{owner}/repos`, `/repos/{owner}/{repo}/commits`, `/languages`, `/releases`.
Пагинация до полного результата, максимум 1000 страниц с ошибкой вместо тихого усечения.
Все даты UTC, полуоткрытый интервал `[since, until)`. SHA используются только в памяти для дедупликации.
Сбор последовательный, чтобы не провоцировать secondary rate limit. На 15 репозиториев обычно около 46 запросов, больше при пагинации.
Без токена GitHub обычно разрешает 60 запросов/час на IP; workflow использует встроенный токен.

403/429, timeout и частичные ошибки становятся `null`/`releaseKnown: false`, а не нулевыми метриками.
Для 5xx — до двух повторов с задержкой. 409 пустой Git-истории означает нулевую активность.
Общий список при ошибке не публикуется. Автоматический сбор пишет новый файл только после валидации.

## Границы

- Runtime браузера не обращается к GitHub API и не получает секретов.
- Публичность проверяется явно: `private === false`, `visibility === public`, owner совпадает.
- DTO задаётся списком разрешённых полей; весь сырой объект GitHub не сериализуется.
- Browser URL репозитория проверяется против owner/name; React экранирует текст, SVG использует XML-escaping.
- В PR workflow нет секретов и deployment. Build job: contents:read; deploy: pages:write + id-token:write.
- Нет PAT, записанного в файлы. Не добавлять `VITE_GITHUB_TOKEN`.

## Визуальная система

Ночной атлас: почти чёрный сине-зелёный фон, мятный акцент, тёплый Java, синий TypeScript.
Space Grotesk для заголовков, DM Sans для текста. Небольшие подписи, тонкие линии, крупный skyline.
День использует отдельные контрастные semantic tokens.
Формы зданий детерминированы. Изменение списка может перестроить сетку; порядок стабилен по repository ID.
Lite сохраняет все репозитории и значения, сокращая только стоимость визуализации.

Для аккаунтов с сотнями/тысячами репозиториев потребуется chunking/LOD по кварталам:
текущая версия рассчитана и собрана для реального портфолио из 15 репозиториев, без искусственного лимита видимых проектов.
